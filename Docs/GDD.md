## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 1인칭 멀티플레이어 장외(링아웃) 슈터 |
| 한 줄 소개 | 공기총으로 적을 밀어내 아레나 밖으로 떨어뜨려라 |
| 핵심 재미 | 체력이 아닌 **위치와 지형**의 싸움. 발밑을 노려 띄우고, 날려 보내는 손맛 |
| 레퍼런스 | GTA 온라인 "업앤아토마이저(Up-n-Atomizer)" |

## 2. 핵심 루프

1. 아레나에서 적을 찾는다
2. 공기탄으로 적(특히 발밑)을 쏴서 띄우고 밀어낸다
3. 적이 떨어지면 마지막으로 민 사람이 킬을 얻는다
4. 떨어진 사람은 잠시 후 리스폰한다
5. 제한 시간 종료 시 최다 킬 플레이어가 우승한다

## 3. 무기 — 공기총

### 3.1 동작 ✅ (사격 로직은 웹 원작 방식 → §13)
- **즉발 판정**: 쏘는 순간 착탄 지점을 정하고 넉백까지 바로 적용한다. **날아가는 탄은 연출일 뿐**이다.
- 착탄 지점은 다음 중 가장 가까운 곳이다.
  1. 조준선이 처음 닿는 지형이나 캐릭터
  2. **근접 신관**: 조준선이 다른 플레이어 몸 중심 근처(초기값 1.3m)를 지나가는 지점. 코앞 60cm 안은 무시한다.
  3. 최대 사거리 끝 (공중 폭발)
- **무적인 플레이어는 탄이 통과한다.** 직격도, 근접 신관도 반응하지 않는다. 밀리지도 않는 사람에게 탄이 터져 낭비되지 않게 하기 위함이다.
- 폭발 반경 안의 캐릭터를 방사형으로 밀어낸다.
  - 방향 = `normalize(캐릭터 중심 - 폭발 지점)`
  - 세기 = 캡슐 표면까지 거리에 따라 선형 감쇠
- **폭발은 벽을 통과하지 않는다.** 폭발 지점에서 캐릭터의 발, 중심, 머리 중 하나라도 지형에 가리지 않아야 밀린다. 낮은 엄폐물 뒤에서 머리만 나와 있어도 밀린다. 다른 캐릭터는 엄폐물로 치지 않는다.
- **자기/남 반경 분리**: 자기 폭발은 기준 반경과 세기를 그대로 쓴다. 남을 칠 때는 배율을 곱한다 (초기값 반경 ×1.6, 세기 ×0.7). 조준은 관대하게 하면서 로켓 점프 감각은 따로 지키기 위함이다.
- **부위별 배율은 없다.** 발밑 바닥을 쏘면 방향에 위쪽 성분이 생겨 캐릭터가 뜨고, 뜨면 지면 마찰이 사라져 멀리 날아간다. "발밑 샷이 강하다"는 이 물리 규칙 하나에서 자연스럽게 나온다.
- 가슴 직격은 수평으로만 밀려서 마찰 때문에 덜 날아간다.
- 연출용 탄은 아무리 멀어도 최대 0.1초 안에 착탄 지점에 도착한다. 넉백은 쏘는 순간 적용되므로, 탄이 늦으면 "맞기 전에 날아가는" 것처럼 보이기 때문이다. 가까운 거리는 원래 탄속이라 탄이 보인다.
- 경위: 처음에는 실제 투사체가 날아가서 판정했다. 그런데 달리면서 발밑을 쏘면 비행 시간 동안 몸이 이동해 결과가 들쭉날쭉했다. 근거리 즉발(2.5m)로 1차 보완한 뒤, 원작의 즉발 판정으로 교체했다. 이에 따라 "탄을 보고 피한다"는 요소는 없어졌다.

### 3.2 자기 넉백 ✅
- 쏜 사람도 자기 폭발 반경 안이면 밀린다. 가까운 적이나 벽을 쏘면 나도 밀린다 (원작과 동일).
- 자기 발밑에 쏘면 로켓 점프가 된다. 이것이 유일한 추가 이동 수단이다.
- "공기총을 공격에 쓸지, 이동이나 복귀에 쓸지" 선택하게 하는 것이 설계 의도다.

### 3.3 탄약 ✅
- 탄약 소모 없이 **자동 충전**된다.

### 3.4 누적 넉백 ✅
- **없음.** 맞은 횟수와 관계없이 같은 규칙으로 밀린다.
- 추후 아이템 등으로 도입할 수 있다 (→ §9 백로그).
- **연타 누적 상한** ✅: 반대로, 공중에서 연달아 맞아 수평 속도가 끝없이 쌓이는 것은 막는다. 남에게 맞아 얻는 수평 속도는 "이번 한 방의 수평 속도 × 1.6" 을 넘지 않는다.
  - 경위: 중력 2배 튜닝 후 3연발(0.12초 간격)로 39m 까지 날아갔다. 한 방(약 14m)의 손맛은 유지하고 연타 과잉만 줄이기 위함.
  - 배율이라 과충전, 펄스 같은 센 한 방은 그대로 세다. 로켓 점프(자기 넉백)에는 적용하지 않는다 (연속 로켓 점프는 이동 기술).

### 3.5 공정성 원칙 ✅
- 무기 성능은 **모든 플레이어가 동일**하다. 성능을 바꾸는 유료·해금 요소는 없다.
- 스킨만 허용한다. 단, 스킨이 경쟁에 영향을 주면 안 된다 (가시성, 크기, 이펙트 크기 등).
- 구현 원칙: **성능 데이터와 외형 데이터를 별도 에셋으로 분리**한다.
- 아이템(§3.6)은 이 원칙에 걸리지 않는다. 맵의 패드에서 **누구나 똑같이 줍는 것**이기 때문이다.

### 3.6 아이템 ✅ (원작 방식)
- **획득: 아이템 패드.** 맵에 놓인 패드를 밟으면 얻는다.
  - 다음에 나올 아이템이 패드 위에 미리 보인다. 언제 무엇이 나올지 보고 움직이는 판단을 만들기 위함이다.
  - 주우면 다시 찰 때까지 비어 있다 (초기값 20초). 다음 아이템은 주운 즉시 정해진다.
  - 내용물과 획득 판정은 서버가 한다. 동시에 밟으면 먼저 닿은 사람만 받는다.
  - 패드마다 나올 목록을 정할 수 있고, 비워 두면 게임 모드의 기본 목록을 쓴다. 한 아이템만 나오게 고정할 수도 있다 (튜토리얼용).
- **종류**
  - 지속형: 줍는 즉시 일정 시간 켜진다. 여러 종류가 동시에 켜질 수 있다. 같은 것을 다시 주우면 시간이 처음부터 다시 흐른다.
  - 사용형: 들고 있다가 사용 키(원작은 F)로 쓴다. 같은 것을 다시 주우면 횟수가 쌓인다. 먼저 주운 것부터 쓴다.
- 죽으면 가진 아이템은 사라진다.
- 사용형 아이템을 쓰면 사격처럼 리스폰 무적이 풀린다 (§5.4).
- 봇도 패드를 밟으면 똑같이 얻는다. 사용형은 BT 의 `Pung Use Item` 으로 쓴다.

| 아이템 | 종류 | 효과 | 초기값 |
|---|---|---|---|
| 과충전 | 지속 12초 | 남을 칠 때 폭발이 세지고 넓어진다. 로켓 점프는 그대로 (맵 설계가 흔들리지 않게) | 세기 ×1.8, 반경 ×1.25 |
| 닻 | 지속 10초 | 거의 밀리지 않는다. 내 로켓 점프도 약해진다 | 받는 넉백 ×0.35 |
| 드럼 탄창 | 지속 15초 | 줍는 즉시 탄이 가득 차고, 충전이 빨라진다 | 충전 속도 ×3 |
| 펄스 | 사용 1회 | 내 주위로 큰 폭발. 나는 밀리지 않는다. 벽 너머는 밀지 않는다 | 세기 ×2, 반경 ×1.6 (공기총 기준) |

- ❓ 2차 후보: 리버스 캡슐(폭발이 끌어당김), 깃털(더 멀리 날고 글라이딩 1회). 둘 다 이동 예측과 얽혀 있어 나중에.
- ❓ 새 아이디어: 표식탄(맞힌 상대가 잠시 넉백을 더 받음, 백로그의 누적 넉백), 자석탄(근접 신관 반경 증가), 산탄, 돌풍(사용형 대시), 지뢰(사용형 설치).
- **임시 외형 (캐릭터):** 눈으로 알아야 하는 지속형(기본: 닻)이 켜진 동안 발밑에 아이템 색 원판(지름 1.6m)이 보인다. 효과의 `Show Placeholder Disc` 로 아이템마다 켜고 끈다. 진짜 이펙트는 나중에 BP 로.
  - 자동 대전 기록에서 "발밑을 맞혀도 조금만 튄다" 의 대부분(남에게 맞은 넉백의 약 16%)이 닻(받는 넉백 ×0.35)이었는데 표시가 없어 알 수 없었다.
- **임시 외형 (패드):** 아트 전까지 C++ 이 엔진 기본 도형으로 그린다. 발판(원기둥) + 아이템 Color 로 칠한 도는 상자 + 이름 글자(에셋 이름에서 `DA_Item_` 을 뗀 것, 비었으면 남은 초). 비면 상자를 숨기고 발판을 어둡게. 충돌 없음. BP 에서 진짜 외형을 만들면 `Use Placeholder Visual` 을 끈다.
- 구조: 아이템마다 `UPungItemData` 에셋 하나. 에셋 안에서 효과 종류를 고르고 그 자리에서 수치를 편집한다. 새 효과는 `UPungItemEffect` 자식 클래스로 만든다.
- 테스트 명령 (호스트 전용): `PungGiveItem <에셋 이름>` (예: `PungGiveItem DA_Item_Pulse`)

### 3.7 구조물 (날릴 수 있는 물체)
- **목적:** 직접 맞히기와 아이템 외에 **지형을 이용한 간접 공격**. 엄폐물 뒤의 상대를 상자로 쳐서 떨어뜨리는 플레이.
- **동작**
  - 공기총 폭발(펄스 포함)은 구조물도 민다. 남을 칠 때와 같은 반경, 세기에 구조물별 배율(무게)을 곱한다. 벽 너머는 밀지 않는다.
  - **날아가는 방향은 쏜 사람의 조준 방향 쪽으로 70% 맞춘다.** 모서리를 쏴도 보는 쪽으로 날아가 노리기 쉽게. 펄스(내 위치에서 터짐)는 해당 없음.
  - 멈춰 있던 구조물은 옆에서 쏴도 살짝 떠오른다 (위쪽 속도 ≥ 수평 속도 × 0.15). 바닥에 끌려 바로 서지 않게. 중력은 1.2배로 낮게 해서 직선에 가깝게 멀리 간다.
  - 날아가는 구조물이 사람에게 부딪히면 **구조물 속도에 비례한 넉백** (위쪽 성분 포함, 최소 1500 보장 = 공기총 직격 수준). 최소 속도 미만이면 밀지 않는다. 맞힌 뒤에는 속도 대부분을 잃는다.
  - **맞힘 판정 여유 60cm:** 몸에 닿지 않아도 표면이 이 거리 안을 스치면 맞은 것으로 친다 (공기총 근접 신관과 같은 역할). 쏜 직후 0.3초는 쏜 사람을 이 판정에서 뺀다.
  - 한 번 날아가는 동안 같은 사람은 한 번만 맞는다 (맞힌 사람은 통과).
  - **킬은 구조물을 날린 사람의 것** (킬 유효 시간 안). **내가 날린 구조물에 나도 맞는다** (자기 넉백 취급).
  - **날아가는 중에도 다시 밀린다.** 지금 속도에 더해져 공중에서 방향을 꺾거나 더 세게 보낼 수 있다.
  - 지형(다른 구조물 포함)에 튕기며, 바닥에서 충분히 느려지면 멈춘다.
  - **멈춰 있을 때만 올라설 수 있다** (엄폐물이자 발판). 밟고 있던 구조물이 날아가면 탄 사람도 같은 속도로 밀린다 (함정 플레이).
  - 멈춘 구조물 아래가 비면 (밑에 있던 구조물이 날아감) 다시 떨어진다.
  - 아레나 밖으로 떨어지면 사라졌다가 잠시 뒤 **원래 자리에** 다시 생긴다. 그 자리에 사람이 있으면 비킬 때까지 기다린다.
  - 공기총 조준선과 폭발 차단 검사에 걸린다 (엄폐물).
- **네트워크: 계산된 궤적.** 물리 시뮬레이션을 쓰지 않는다. 서버가 한 구간(시작 위치, 속도, 서버 시각)을 보내면 모두가 같은 포물선을 계산한다. 튕기거나 사람을 맞히면 서버가 새 구간을 보낸다. 클라이언트는 막히면 그 자리에서 다음 구간을 기다린다.
  - 회전은 수평 회전만 (연출). 구르거나 쌓인 것이 무너지는 연출은 없다.
- 1차 범위 밖: 봇이 구조물을 노려 쏘기 (봇에게는 장애물일 뿐), 걸어서 밀기.
- 구조: 종류마다 `UPungPropData` 에셋, 외형은 `APungProp` 의 BP 자식.

## 4. 이동 ✅

- 기본 이동 + **기본 점프만** 제공한다.
- 더블 점프나 대시는 없다. 추가 이동은 자기 넉백으로만 한다.
- 🧪 공중 제어 정도(Air Control)는 프로토타입에서 튜닝한다.
- **넉백 후 조작력 감소** ✅ (원작 방식): 넉백 직후 잠시(초기값 0.45초) 이동 입력 효과가 줄어든다 (초기값 10%). 맞은 사람이 키를 눌러 넉백을 상쇄하지 못하게 하기 위함이다. 자기 넉백(로켓 점프)에도 적용된다.
- **맞아서 뜨면 착지할 때까지 공중 조작 감소** ✅: 남의 폭발로 위로 뜨면 착지할 때까지 이동 입력이 15% 로 줄어든다. 봇의 길찾기 이동은 아예 멈춘다.
  - 경위: 플레이 테스트에서 "맞혀도 잘 안 날아간다". 공중 제어(0.3)가 커서, 0.45초 감소가 끝난 뒤 반대 방향 키(봇은 Move To)로 수평 넉백을 1초도 안 돼 지워 버렸다. 계산상 발밑 샷 비거리 약 12m 가 2~3m 로 줄어든다.
  - 내 로켓 점프는 기본적으로 해당하지 않는다 (공중 조작감 유지). 옵션으로 켤 수 있다.
- **폭발 점프 유예** ✅ (원작 방식): 땅에서 폭발을 맞아 떠오른 직후 잠시(초기값 0.22초)는 공중이어도 점프를 받아준다. 이때 점프 속도는 폭발로 생긴 위쪽 속도에 **더해진다**. "점프 → 발밑 사격"과 "발밑 사격 → 점프"가 같은 결과가 되게 하기 위함이다.
  - 네트워크: 서버는 원격 플레이어의 유예 시간을 핑(왕복 지연)만큼 늘려 판정한다.

## 5. 규칙

### 5.1 사망 ✅
- 아레나 밖으로 떨어지면 사망한다 (Kill Z / 사망 볼륨).
- ❓ 그 밖의 사망 조건은 아레나 디자인 때 결정한다.

### 5.2 킬 판정 ✅
- 떨어진 플레이어를 **마지막으로 민 사람**이 킬을 얻는다.
- 그 "마지막 밀기"가 유효한 시간이 있다 (🧪 시간 값은 테스트 후 결정).
  - 유효 시간 안에 떨어지면 마지막으로 민 사람의 킬이다.
  - 유효 시간이 지나서 떨어지면 자멸로 처리한다.
- 🧪 자기 넉백도 "마지막으로 민 것"을 덮어쓰는지 테스트해야 한다. 예: A가 B를 밀고, B가 로켓 점프하다 떨어지면 킬을 A에게 줄지 결정해야 한다.

### 5.3 자멸 ✅
- 스스로 떨어져도 **감점은 없다**.

### 5.4 리스폰 ✅
- 사망 후 **몇 초 대기**한 뒤 리스폰한다 (🧪 시간 값 테스트).
- 스폰 위치: 정해진 스폰 지점들 중 **살아 있는 다른 플레이어들에게서 가장 먼 곳** (상위 2곳 중 랜덤). 적 바로 앞 리스폰을 줄이고, 한 지점에 여러 명이 겹쳐 스폰되지 않게 한다.
  - 엔진 기본 방식은 지형과 겹치는 지점(패드 위 등)을 "차 있음"으로 보고 그중에서 다시 랜덤으로 골라 겹침이 생겼다 (자동 대전 기록에서 매 판 시작 직후 1m 거리 맞쏘기로 발견).
  - 매치 시작 시에는 전원의 몸을 먼저 지운 뒤 차례로 스폰해서, 서로 먼 곳에 흩어진다.
- 리스폰 직후 **무적**이다.
  - 무적 = 넉백을 받지 않음. 남의 탄도 몸을 통과한다 (§3.1)
  - 지속 시간이 끝나면 해제된다 (🧪 시간 값 테스트)
  - **무적 중 공기총을 쏘면 즉시 해제된다.**
  - 무적 상태임을 다른 플레이어가 볼 수 있어야 한다 (이펙트 등).
- **리스폰 대기 중 관전** ✅
  - 나를 떨어뜨린 사람을 3인칭으로 따라간다. 그 사람도 몸이 없으면(죽음) 아레나 전경을 보다가, 다시 나타나면 따라간다.
  - 자멸이면 아레나 전경을 비스듬히 위에서 내려다본다. 기본은 스폰 지점들의 평균을 중심으로 잡고, 맵에 `PungOverview` 태그 액터가 있으면 그 위치와 방향을 쓴다.
  - 관전하는 사람의 화면에서만 동작한다 (네트워크 부담 없음). 리스폰하면 원래 시점으로 돌아온다.
  - UI 용: `APungPlayerController` 의 `OnSpectateChanged(관전 중, 대상)`, `IsSpectating()`, `GetSpectateTarget()`.

### 5.5 킬 태그, 연속 킬, 현상금
- **킬 태그 (스타일):** 킬 피드 문장 뒤에 어떻게 떨어뜨렸는지 붙인다. 예: `A  →  B   공중 · 3연타`
  | 태그 | 조건 |
  |---|---|
  | 공중 | 마지막으로 맞을 때 상대가 공중에 떠 있었다 |
  | N연타 | 킬 유효 시간 안에 같은 사람에게 3번 이상 맞았다 |
  | 구조물 / 펄스 | 마지막으로 밀린 것이 날아온 구조물 / 펄스 |
  | 자폭 유도 | 상대가 마지막에 자기 폭발로 떨어졌는데, 킬러가 민 직후라 킬러의 것이 됐다 |
  | 복수 | 나를 마지막으로 떨어뜨린 사람을 떨어뜨렸다 |
  | 현상금 +1 | 현상금이 걸린 사람을 떨어뜨렸다 |
  | N연속 / N연속! 현상금 | 킬러의 연속 킬 (2 이상), 현상금이 막 걸렸을 때 |
- **연속 킬:** 죽지 않고 이어 간 킬 수. 매치 진행 중만 센다. 죽으면 0.
- **현상금:** 3연속 킬이면 현상금이 걸린다. 그 사람을 떨어뜨리면 **킬 +1 보너스** (점수 = 킬 수라 킬로 친다). 죽으면 사라진다. 1등 견제 장치.
- 판정은 서버. 킬 피드는 `OnPlayerFellDetailed` 의 킬 내용(`FPungKillInfo`)으로 C++ 이 문장을 만든다. 기록 CSV(falls) 에도 태그와 연속 킬이 남는다.

| 인원 | ❓ 상한 미정. 8인 상한을 가정해 설계하고 4인으로 테스트하는 것이 잠정안 |

### 6.1 매치 흐름 ✅
```
대기 (자유 연습) ──시작 조건──▶ 카운트다운 3초 ──▶ 진행 ──▶ 결과 10초 ──▶ 맵 다시 열기 ──▶ 5초 뒤 카운트다운
```
- **대기:** 맵이 열리거나 방을 만들면 여기서 시작한다. 이동, 사격, 낙사, 리스폰, 아이템 모두 된다. **점수는 세지 않는다.** 킬 피드와 관전은 나온다. 매치 타이머는 흐르지 않는다.
- **시작 조건:** 호스트가 `PungStartMatch`, 또는 사람(봇 제외) 2명 이상이 모이면 10초 뒤 자동. 그 사이 2명 아래로 줄면 취소.
- **카운트다운:** 전원(봇 포함)을 스폰 지점에서 새로 스폰하고 킬/사망을 0 으로 지운다. 이동과 사격이 막힌다.
- **재시작:** 결과 화면 뒤 같은 맵을 다시 열면 대기 없이 5초 뒤 카운트다운 (다른 사람이 맵을 다시 불러올 시간).
- 이유: 친구가 접속하는 동안 점수가 쌓이지 않게, 모두 같은 조건에서 시작하게.

## 7.5 봇 ✅

- **호스트가 직접 넣고 뺀다.** 빈자리 자동 채우기는 없다. 사람과 봇을 합쳐 정원을 넘지 않는다 (세션이 없으면 8명).
  - 넣은 봇(등급 포함)은 매치가 다시 시작돼도 유지된다.
- **등급.** 같은 C++ 컨트롤러에 BP 를 등급마다 따로 만들어 BT 와 프로필을 바꾼다. 게임 모드의 `Bot Controller Class` 가 기본 등급, `Bot Tiers` (이름 → 컨트롤러 BP, 이름 앞부분) 가 추가 등급.
  - 기본: `BP_PungAIController` + `BT_PungBot` + `DA_BotProfile_Normal` (C++ 위치 찾기 노드)
  - 똑똑함(`Smart`): `BP_PungAIController_Smart` + `BT_PungBot_Smart` + `DA_BotProfile_Smart` (EQS 로 자리 잡기, 위협 회피, 탄 관리, 사냥감 고르기)
  - (임시) 프로필의 `Body Look` 으로 등급마다 몸 머티리얼이나 색을 바꿔 눈으로 구분한다. 빙의할 때 서버가 정하고 모두에게 복제된다. 정식 스킨이 생기면 걷어낸다.
  - 사람이 들어올 때 봇이 자동으로 빠지지는 않는다. 사람의 접속은 사람 수로만 정원을 검사한다.
- **사람과 같은 규칙.** 같은 캐릭터, 같은 공기총, 같은 판정, 같은 넉백 후 조작력 감소를 쓴다 (§3.5). 점수판, 킬 판정, 우승도 사람과 똑같이 친다.
  - 점수판의 봇 표시는 UI 에서 `APungPlayerState::IsBot()` 으로 한다. 이름은 "Bot 1" 같은 형태 (등급마다 앞부분을 바꿀 수 있음. 예: "Smart Bot 2").
- **서버에만 있다.** 클라이언트에게는 다른 플레이어로 보인다.
- **감각 (AI Perception 은 쓰지 않고 BT 노드에서 직접 판정)**
  - 시각: 인식 거리 20m + 가리지 않음 + (시야 좌우 60° / 근접 5m / 최근 본 지금 대상 2초). 가려지면 바로 놓친다.
  - 청각: 15m 안에서 누가 총을 쏘면 쏜 사람을 알아챈다 (시야각 밖이어도 대상 가능, 보이기는 해야 함). 폭발음은 그 자리만. 노릴 적이 없으면 소리 난 쪽을 돌아본다. 1.5초 기억.
  - 알아챈 적의 마지막 위치를 5초 기억한다 (EQS 후퇴 쿼리 등은 이 기억만 쓴다).
- **구조: 행동은 BT 에서 조립한다.** C++ 는 BT 부품과 실행 껍데기만 제공한다.

  | 노드 | 종류 | 역할 |
  |---|---|---|
  | `Pung Find Target` | Service | "거리 - 가산점" 이 가장 작은 적 → BB (Object). 가산점: 가장자리 근처, 공중에 뜸, 지금 노리는 상대, (프로필에서 켜면) 탄이 거의 없는 상대, 나를 노리는 상대. 무적 상대 제외. 선택 키: 공중 여부, 가장자리 여부 (Bool) |
  | `Pung Detect Threat` | Service | 나를 노리는 적(조준선이 내 몸/발과 6° 안, 서로 보임, 탄 있음, 내 시야 좌우 90° 안 또는 근접/총소리)을 반응 시간 0.25초 뒤 알아챔 → BB (Bool, 선택 Object) |
  | `Pung Check Edge` | Service | 주변에 바닥 없는 곳이 있으면 → BB (Bool). 공중에서는 갱신 안 함 |
  | `Pung Aim And Fire` | Task | 반응 시간 동안 대상을 바라보다가 오차를 섞어 발사. 땅에 있는 상대는 확률로 발밑 조준. 상대가 뜨면 확률로 연사(저글). 내가 가장자리인데 내 폭발 범위 안을 쏘게 되면 안 쏨 |
  | `Pung Find Combat Location` | Task | 대상과 싸우기 좋은 자리 → BB (Vector). 대상 주변 6~13m 고리 중: 실제로 걸어서 갈 수 있음 (경로 검사), 내 발밑 안전, 대상이 보임, **내 쪽에서 쏘면 대상이 가장자리로 밀려 나가는 자리**, 높은 곳 선호, 먼 이동 회피 |
  | `Pung Find Roam Location` | Task | 적이 없을 때 돌아다닐 NavMesh 지점 → BB (Vector). 가장자리 제외, 아레나 중심과 차 있는 아이템 패드 쪽 선호, 최근 간 곳 회피 |
  | `Pung Find Safe Location` | Task | 낭떠러지 반대쪽, 주변에 바닥이 많은 NavMesh 지점 → BB (Vector) |
  | `Pung Has Charge` | Decorator | 충전 N발 이상이면 통과 (중단 모드 미지원) |
  | `Pung Use Item` | Task | 들고 있는 사용형 아이템(펄스 등) 사용. 없으면 실패 |
  | `Pung Find Dodge Location` | Task | 위협의 조준선 옆(좌우, 비스듬히 앞)으로 비켜설 자리 중 주변 바닥이 가장 많은 곳 → BB (Vector). 확률로 점프 (가장자리 근처 제외) |

- 1차 범위: 적 찾기, 조준 오차를 둔 발밑/몸 사격, 낭떠러지 피하기.
- 2차 ✅: 떨어뜨리기 좋은 적 우선 (가장자리, 공중), 저글 연사, 자기 폭발 안전 검사, 배회 (아이템 패드 쪽).

- 4차 (똑똑한 봇 등급): EQS 로 자리 잡기 (공격/수비/후퇴/아이템), 위협 감지와 회피, 탄 관리 (2발 미만이면 물러나 충전, `Pung Has Charge` 반전), 사냥감 고르기 (탄 없는 상대, 나를 노리는 상대), 펄스는 가장자리 근처 적이 범위 안일 때만. 기본 봇은 그대로 둔다.
- 보류: **밀려 떨어질 때 로켓 점프로 복귀.** 지금 규칙에서는 사람도 거의 못 한다. 공중에서 내 근처에 폭발을 만들려면 탄이 무언가에 맞아야 하는데(근접 신관은 남의 몸에만 반응, 아무것도 안 맞으면 사거리 끝에서 폭발), 아레나 밖에는 쏠 바닥이 없고 아레나 벽을 쏘면 바깥으로 밀린다. 복귀 플레이를 넣으려면 먼저 사격 규칙(예: 공중 폭발 거리 조절)을 정해야 한다 (❓ 기획 결정).

## 7.6 자동 대전과 기록 (밸런스 데이터)

- **목적:** 봇끼리 매치를 반복시켜 밸런스 데이터를 모은다. 사람의 손맛은 직접 테스트로 보완한다.
  - 지금은 1인칭 템플릿 맵을 그레이박스로 삼는다. 등급 비교, 넉백, 아이템 같은 상대 비교는 이 맵으로도 의미가 있고, 위험 지점 같은 맵 고유 데이터는 아레나를 만든 뒤 다시 모은다.
- **자동 대전 모드 (`-PungAutoMatch`):** 사람을 기다리지 않고 곧바로 카운트다운 → 매치 → 1초 뒤 다음 매치를 반복하고, 정해진 판 수를 마치면 종료한다.
  - 로컬 플레이어는 스폰하지 않고 관전자로 둔다 (점수판, 우승, 기록에서 제외).
  - 실행 인자: `-PungBots=Default:2,Smart:2` (등급:수), `-PungMatches=10` (0=무한), `-PungMatchDuration=120` (0=게임 모드 값), `-PungTimeScale=1` (시간 팽창, 크면 물리 결과가 조금 달라질 수 있음)
  - `Run-AutoMatch.bat` 이 에디터 빌드로 화면 없이(`-nullrhi -nosound -nosteam`) 실행한다. 패키징한 exe 도 같은 인자로 돌릴 수 있다.
  - `AutoMatch-Launcher.bat` (GUI, `Tools/AutoMatchLauncher.ps1`, Windows 기본 PowerShell): 등급별 봇 수, 판 수, 매치 시간, 속도, 동시 실행 수, 화면 보기 여부를 고르고 실행한다. 에디터 빌드와 패키징 exe 모두 지원. 설정은 `Saved/AutoMatchLauncher.json`
  - 화면으로 볼 때는 로컬 플레이어가 처음부터 아레나 전경 카메라를 본다.
  - 기록 폴더 이름에 프로세스 번호를 붙여 여러 개를 동시에 돌려도 겹치지 않는다.
- **기록 (서버 전용, 매치 진행 중만):** `Saved/Telemetry/<실행 시각>_<프로세스 번호>/` 에 CSV.
  - 켜는 법: 자동 대전 모드, 실행 인자 `-PungTelemetry`, 또는 콘솔 `pung.Telemetry 1` (사람끼리 플레이 기록도 남길 수 있다)

  | 파일 | 한 줄 | 열 |
  |---|---|---|
  | `knockbacks.csv` | 넉백 한 번 (로켓 점프 포함) | 매치, 시간, 민 사람/등급, 맞은 사람/등급, 자기 폭발 여부, 세기(전체/수평/수직), 맞은 사람이 공중/가장자리였는지, 두 사람 위치, 거리 |
  | `falls.csv` | 낙사 한 번 | 매치, 시간, 떨어진 사람/등급, 킬 가져간 사람/등급 (없으면 자멸), 킬 유효 시간 안에 그 사람에게 맞은 횟수, 마지막으로 맞은 위치, 맞은 뒤 떨어지기까지 시간, 생존 시간 |
  | `items.csv` | 아이템 줍기/쓰기 | 매치, 시간, 사람/등급, pickup/use, 아이템 에셋 이름, 위치 |
  | `matches.csv` | 매치 끝, 사람마다 | 매치, 맵, 길이, 이름, 등급, 킬, 사망, 우승 여부 |

  - 등급 열: 사람 `Human`, 기본 봇 `Default`, 나머지는 등급 이름.

### UI 에서 쓸 데이터

> HUD 는 `UPungHUDWidget` 을 부모로 만들고 정해진 이름의 위젯을 배치하면 C++ 이 아래 값을 채운다 (BindWidget). 위젯 이름은 `Docs/EditorChecklist.md` §10.

## 13. 웹 원작 레퍼런스 (PUNG!)

- 저장소: https://github.com/Jokkilook/MiniGameChallenge/tree/main/Pung (WebGL, 직접 제작)
- 방침: **수치를 그대로 옮기지 않는다.** 로직과 설계 의도만 가져오고, 수치는 언리얼 버전에서 따로 튜닝한다.

### 가져온 것
- 사격 로직 (§3.1): 즉발 판정, 연출용 탄, 근접 신관, 공중 폭발, 자기/남 반경 분리
- 넉백 후 조작력 감소, 폭발 점프 유예 (§4)
- 아이템 패드와 아이템 4종: 과충전, 닻, 드럼 탄창, 펄스 (§3.6). 수치는 출발점으로 원작 값을 썼다

### 아직 안 가져온 것 (후보)
| 항목 | 원작 동작 |
|---|---|
| 리스폰 무적 범위 | 무적은 남의 넉백만 막고, 자기 로켓 점프는 허용 |
| 아이템 2종 | 리버스 캡슐, 깃털 (나머지 4종은 가져옴, §3.6) |
