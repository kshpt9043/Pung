# Pung — Game Design Document

- 엔진: Unreal Engine 5.8 (C++ + Blueprint)
- 목표 플랫폼: Steam (PC)
- 최종 갱신: 2026-10-06

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 1인칭 멀티플레이어 장외(링아웃) 슈터 |
| 한 줄 소개 | 공기총으로 적을 밀어내 아레나 밖으로 떨어뜨려라 |
| 핵심 재미 | 체력이 아닌 **위치와 지형**의 싸움. 발밑을 노려 띄우고, 날려 보내는 손맛 |
| 레퍼런스 | GTA 온라인 "업앤아토마이저(Up-n-Atomizer)" |

## 2. 핵심 루프

1. 아레나에서 적을 찾는다
2. 공기탄으로 적(특히 발밑)을 쏴서 띄우고 밀어낸다
3. 적이 떨어지면 마지막으로 민 사람이 킬을 얻는다
4. 떨어진 사람은 잠시 후 리스폰한다
5. 제한 시간 종료 시 최다 킬 플레이어가 우승한다

## 3. 무기 — 공기총

### 3.1 동작 ✅ (사격 로직은 웹 원작 방식 → §13)
- **즉발 판정**: 쏘는 순간 착탄 지점을 정하고 넉백까지 바로 적용한다. **날아가는 탄은 연출일 뿐**이다.
- 착탄 지점은 다음 중 가장 가까운 곳이다.
  1. 조준선이 처음 닿는 지형이나 캐릭터
  2. **근접 신관**: 조준선이 다른 플레이어 몸 중심 근처(초기값 1.3m)를 지나가는 지점. 코앞 60cm 안은 무시한다.
  3. 최대 사거리 끝 (공중 폭발)
- **무적인 플레이어는 탄이 통과한다.** 직격도, 근접 신관도 반응하지 않는다. 밀리지도 않는 사람에게 탄이 터져 낭비되지 않게 하기 위함이다.
- 폭발 반경 안의 캐릭터를 방사형으로 밀어낸다.
  - 방향 = `normalize(캐릭터 중심 - 폭발 지점)`
  - 세기 = 캡슐 표면까지 거리에 따라 선형 감쇠
- **폭발은 벽을 통과하지 않는다.** 폭발 지점에서 캐릭터의 발, 중심, 머리 중 하나라도 지형에 가리지 않아야 밀린다. 낮은 엄폐물 뒤에서 머리만 나와 있어도 밀린다. 다른 캐릭터는 엄폐물로 치지 않는다.
- **자기/남 반경 분리**: 자기 폭발은 기준 반경과 세기를 그대로 쓴다. 남을 칠 때는 배율을 곱한다 (초기값 반경 ×1.6, 세기 ×0.82). 조준은 관대하게 하면서 로켓 점프 감각은 따로 지키기 위함이다.
- **부위별 배율은 없다.** 발밑 바닥을 쏘면 방향에 위쪽 성분이 생겨 캐릭터가 뜨고, 뜨면 지면 마찰이 사라져 멀리 날아간다. "발밑 샷이 강하다"는 이 물리 규칙 하나에서 자연스럽게 나온다.
- 가슴 직격은 수평으로만 밀려서 마찰 때문에 덜 날아간다.
- 연출용 탄은 아무리 멀어도 최대 0.1초 안에 착탄 지점에 도착한다. 넉백은 쏘는 순간 적용되므로, 탄이 늦으면 "맞기 전에 날아가는" 것처럼 보이기 때문이다. 가까운 거리는 원래 탄속이라 탄이 보인다.
- 경위: 처음에는 실제 투사체가 날아가서 판정했다. 그런데 달리면서 발밑을 쏘면 비행 시간 동안 몸이 이동해 결과가 들쭉날쭉했다. 근거리 즉발(2.5m)로 1차 보완한 뒤, 원작의 즉발 판정으로 교체했다. 이에 따라 "탄을 보고 피한다"는 요소는 없어졌다.

### 3.2 자기 넉백 ✅
- 쏜 사람도 자기 폭발 반경 안이면 밀린다. 가까운 적이나 벽을 쏘면 나도 밀린다 (원작과 동일).
- 자기 발밑에 쏘면 로켓 점프가 된다. 이것이 유일한 추가 이동 수단이다.
- "공기총을 공격에 쓸지, 이동이나 복귀에 쓸지" 선택하게 하는 것이 설계 의도다.

### 3.3 탄약 ✅
- 탄약 소모 없이 **자동 충전**된다.

### 3.4 누적 넉백 ✅
- **없음.** 맞은 횟수와 관계없이 같은 규칙으로 밀린다.
- 추후 아이템 등으로 도입할 수 있다 (→ §9 백로그).
- **연타 누적 상한** ✅: 반대로, 공중에서 연달아 맞아 수평 속도가 끝없이 쌓이는 것은 막는다. 남에게 맞아 얻는 수평 속도는 "이번 한 방의 수평 속도 × 1.6" 을 넘지 않는다.
  - 경위: 중력 2배 튜닝 후 3연발(0.12초 간격)로 39m 까지 날아갔다. 한 방(약 14m)의 손맛은 유지하고 연타 과잉만 줄이기 위함.
  - 배율이라 과충전, 펄스 같은 센 한 방은 그대로 세다. 로켓 점프(자기 넉백)에는 적용하지 않는다 (연속 로켓 점프는 이동 기술).

### 3.5 공정성 원칙 ✅
- 무기 성능은 **모든 플레이어가 동일**하다. 성능을 바꾸는 유료·해금 요소는 없다.
- 스킨만 허용한다. 단, 스킨이 경쟁에 영향을 주면 안 된다 (가시성, 크기, 이펙트 크기 등).
- 구현 원칙: **성능 데이터와 외형 데이터를 별도 에셋으로 분리**한다.
- 아이템(§3.6)은 이 원칙에 걸리지 않는다. 맵의 패드에서 **누구나 똑같이 줍는 것**이기 때문이다.

### 3.6 아이템 ✅ (원작 방식)
- **획득: 아이템 패드.** 맵에 놓인 패드를 밟으면 얻는다.
  - 다음에 나올 아이템이 패드 위에 미리 보인다. 언제 무엇이 나올지 보고 움직이는 판단을 만들기 위함이다.
  - 주우면 다시 찰 때까지 비어 있다 (초기값 20초). 다음 아이템은 주운 즉시 정해진다.
  - 내용물과 획득 판정은 서버가 한다. 동시에 밟으면 먼저 닿은 사람만 받는다.
  - 패드마다 나올 목록을 정할 수 있고, 비워 두면 게임 모드의 기본 목록을 쓴다. 한 아이템만 나오게 고정할 수도 있다 (튜토리얼용).
- **종류**
  - 지속형: 줍는 즉시 일정 시간 켜진다. 여러 종류가 동시에 켜질 수 있다. 같은 것을 다시 주우면 시간이 처음부터 다시 흐른다.
  - 사용형: 들고 있다가 사용 키(원작은 F)로 쓴다. 같은 것을 다시 주우면 횟수가 쌓인다. 먼저 주운 것부터 쓴다.
- 죽으면 가진 아이템은 사라진다.
- 사용형 아이템을 쓰면 사격처럼 리스폰 무적이 풀린다 (§5.4).
- 봇도 패드를 밟으면 똑같이 얻는다. 사용형은 BT 의 `Pung Use Item` 으로 쓴다.

| 아이템 | 종류 | 효과 | 초기값 |
|---|---|---|---|
| 과충전 | 지속 12초 | 남을 칠 때 폭발이 세지고 넓어진다. 로켓 점프는 그대로 (맵 설계가 흔들리지 않게) | 세기 ×1.8, 반경 ×1.25 |
| 닻 | 지속 10초 | 거의 밀리지 않는다. 내 로켓 점프도 약해진다 | 받는 넉백 ×0.35 |
| 드럼 탄창 | 지속 15초 | 줍는 즉시 탄이 가득 차고, 충전이 빨라진다 | 충전 속도 ×3 |
| 펄스 | 사용 1회 | 내 주위로 큰 폭발. 나는 밀리지 않는다. 벽 너머는 밀지 않는다 | 세기 ×2, 반경 ×1.6 (공기총 기준) |

- ❓ 2차 후보: 리버스 캡슐(폭발이 끌어당김), 깃털(더 멀리 날고 글라이딩 1회). 둘 다 이동 예측과 얽혀 있어 나중에.
- ❓ 새 아이디어: 표식탄(맞힌 상대가 잠시 넉백을 더 받음, 백로그의 누적 넉백), 자석탄(근접 신관 반경 증가), 산탄, 돌풍(사용형 대시), 지뢰(사용형 설치).
- 구조: 아이템마다 `UPungItemData` 에셋 하나. 에셋 안에서 효과 종류를 고르고 그 자리에서 수치를 편집한다. 새 효과는 `UPungItemEffect` 자식 클래스로 만든다.
- 테스트 명령 (호스트 전용): `PungGiveItem <에셋 이름>` (예: `PungGiveItem DA_Item_Pulse`)

## 4. 이동 ✅

- 기본 이동 + **기본 점프만** 제공한다.
- 더블 점프나 대시는 없다. 추가 이동은 자기 넉백으로만 한다.
- 🧪 공중 제어 정도(Air Control)는 프로토타입에서 튜닝한다.
- **넉백 후 조작력 감소** ✅ (원작 방식): 넉백 직후 잠시(초기값 0.45초) 이동 입력 효과가 줄어든다 (초기값 10%). 맞은 사람이 키를 눌러 넉백을 상쇄하지 못하게 하기 위함이다. 자기 넉백(로켓 점프)에도 적용된다.
- **맞아서 뜨면 착지할 때까지 공중 조작 감소** ✅: 남의 폭발로 위로 뜨면 착지할 때까지 이동 입력이 15% 로 줄어든다. 봇의 길찾기 이동은 아예 멈춘다.
  - 경위: 플레이 테스트에서 "맞혀도 잘 안 날아간다". 공중 제어(0.3)가 커서, 0.45초 감소가 끝난 뒤 반대 방향 키(봇은 Move To)로 수평 넉백을 1초도 안 돼 지워 버렸다. 계산상 발밑 샷 비거리 약 12m 가 2~3m 로 줄어든다.
  - 내 로켓 점프는 기본적으로 해당하지 않는다 (공중 조작감 유지). 옵션으로 켤 수 있다.
- **폭발 점프 유예** ✅ (원작 방식): 땅에서 폭발을 맞아 떠오른 직후 잠시(초기값 0.22초)는 공중이어도 점프를 받아준다. 이때 점프 속도는 폭발로 생긴 위쪽 속도에 **더해진다**. "점프 → 발밑 사격"과 "발밑 사격 → 점프"가 같은 결과가 되게 하기 위함이다.
  - 네트워크: 서버는 원격 플레이어의 유예 시간을 핑(왕복 지연)만큼 늘려 판정한다.

## 5. 규칙

### 5.1 사망 ✅
- 아레나 밖으로 떨어지면 사망한다 (Kill Z / 사망 볼륨).
- ❓ 그 밖의 사망 조건은 아레나 디자인 때 결정한다.

### 5.2 킬 판정 ✅
- 떨어진 플레이어를 **마지막으로 민 사람**이 킬을 얻는다.
- 그 "마지막 밀기"가 유효한 시간이 있다 (🧪 시간 값은 테스트 후 결정).
  - 유효 시간 안에 떨어지면 마지막으로 민 사람의 킬이다.
  - 유효 시간이 지나서 떨어지면 자멸로 처리한다.
- 🧪 자기 넉백도 "마지막으로 민 것"을 덮어쓰는지 테스트해야 한다. 예: A가 B를 밀고, B가 로켓 점프하다 떨어지면 킬을 A에게 줄지 결정해야 한다.

### 5.3 자멸 ✅
- 스스로 떨어져도 **감점은 없다**.

### 5.4 리스폰 ✅
- 사망 후 **몇 초 대기**한 뒤 리스폰한다 (🧪 시간 값 테스트).
- 스폰 위치: 정해진 스폰 지점들 중 **랜덤**으로 고른다.
- 리스폰 직후 **무적**이다.
  - 무적 = 넉백을 받지 않음. 남의 탄도 몸을 통과한다 (§3.1)
  - 지속 시간이 끝나면 해제된다 (🧪 시간 값 테스트)
  - **무적 중 공기총을 쏘면 즉시 해제된다.**
  - 무적 상태임을 다른 플레이어가 볼 수 있어야 한다 (이펙트 등).
- **리스폰 대기 중 관전** ✅
  - 나를 떨어뜨린 사람을 3인칭으로 따라간다. 그 사람도 몸이 없으면(죽음) 아레나 전경을 보다가, 다시 나타나면 따라간다.
  - 자멸이면 아레나 전경을 비스듬히 위에서 내려다본다. 기본은 스폰 지점들의 평균을 중심으로 잡고, 맵에 `PungOverview` 태그 액터가 있으면 그 위치와 방향을 쓴다.
  - 관전하는 사람의 화면에서만 동작한다 (네트워크 부담 없음). 리스폰하면 원래 시점으로 돌아온다.
  - UI 용: `APungPlayerController` 의 `OnSpectateChanged(관전 중, 대상)`, `IsSpectating()`, `GetSpectateTarget()`.

## 7. 네트워크 ✅

- **리슨 서버** (플레이어 중 한 명이 호스트)
- 알려진 한계:
  - 호스트가 나가면 매치가 종료된다 (호스트 이전 미지원)
  - 호스트에게 핑 이점이 있고, 호스트 권한으로 치트가 가능하다
- 넉백, 킬 판정, 점수는 **서버 권한**으로 처리한다.
- 사격 조준 ✅: 쏜 사람 화면의 눈 위치와 조준 방향을 서버에 보낸다. 서버는 그 값으로 판정한다.
  - 방향은 그대로 받는다. 서버의 컨트롤 회전은 이동 패킷을 따라 늦게 와서, 돌면서 쏘면 엉뚱한 방향으로 판정되기 때문이다.
  - 눈 위치는 서버가 아는 위치에서 허용 오차(초기값 2m) 안으로 잘라낸다. 둘 사이에 벽이 있으면 서버 위치를 쓴다 (벽 너머 사격 방지).
  - 표적의 위치는 서버 기준이다 (과거 위치 되감기는 하지 않음).
- 사격 연출 ✅: 쏜 사람은 서버 응답을 기다리지 않고 자기 화면에서 바로 탄을 띄운다 (착탄 지점은 예측값). 다른 사람에게는 서버가 멀티캐스트로 띄운다.
- Steam 세션 ✅ (Terminus 와 같은 구성)
  - 방은 스팀 로비로 광고하고, 접속은 호스트의 리슨 서버로 한다 (SteamSockets 넷 드라이버, 실패 시 IP 넷 드라이버).
  - 개발 중에는 AppID 480(Spacewar)을 쓴다. 전 세계 개발자가 같이 쓰므로 빌드 태그(`PUNGBUILD=Dev`)로 Pung 방만 검색한다. 자체 AppID 를 받으면 교체한다.
  - 매치 중에도 들어올 수 있다. 정원이 차면 호스트가 접속을 거절한다.
  - 호스트가 나가거나 연결이 끊기면 세션을 정리하고 기본 맵(혼자 하는 상태)으로 돌아간다.
  - 친구 초대: 스팀 오버레이 초대 창, 초대 수락 시 바로 참가.
  - ❓ 매치메이킹(자동 매칭), 방 이름/비밀번호는 나중에.
  - 테스트: Steam 을 켜고 **Standalone** 으로 실행해야 한다 (PIE 에서는 Steam 이 동작하지 않음). 프로젝트 루트의 `Run-Standalone.bat` 사용 (`nosteam` 인자로 Steam 없이 실행). 두 PC, 서로 다른 스팀 계정이 필요하다.
- 세션 디버그 콘솔 명령 (UI 생기기 전까지, `APungPlayerController`)

  | 명령 | 동작 |
  |---|---|
  | `PungHost [인원=8]` | 방을 만들고 지금 맵을 리슨 서버로 다시 연다 |
  | `PungFind` | 방을 검색해 화면에 번호와 함께 띄운다 |
  | `PungJoin [번호=0]` | 마지막 검색 결과의 번호로 참가 |
  | `PungLeave` | 방에서 나가 기본 맵으로 |
  | `PungInvite` | 스팀 친구 초대 창 |
  | `PungSession` | 현재 세션 상태 출력 |
  | `PungBuildFilter 0/1` | 빌드 태그 필터 끄기/켜기 (검색 자체가 되는지 확인용) |

## 7.5 봇 ✅

- **호스트가 직접 넣고 뺀다.** 빈자리 자동 채우기는 없다. 사람과 봇을 합쳐 정원을 넘지 않는다 (세션이 없으면 8명).
  - 넣은 봇 수는 매치가 다시 시작돼도 유지된다.
  - 사람이 들어올 때 봇이 자동으로 빠지지는 않는다. 사람의 접속은 사람 수로만 정원을 검사한다.
- **사람과 같은 규칙.** 같은 캐릭터, 같은 공기총, 같은 판정, 같은 넉백 후 조작력 감소를 쓴다 (§3.5). 점수판, 킬 판정, 우승도 사람과 똑같이 친다.
  - 점수판의 봇 표시는 UI 에서 `APungPlayerState::IsBot()` 으로 한다. 이름은 "Bot 1" 같은 형태.
- **서버에만 있다.** 클라이언트에게는 다른 플레이어로 보인다.
- **구조: 행동은 BT 에서 조립한다.** C++ 는 BT 부품과 실행 껍데기만 제공한다.

  | 노드 | 종류 | 역할 |
  |---|---|---|
  | `Pung Find Target` | Service | 가장 가깝고 보이는 적 → BB (Object). 무적 상대 제외 |
  | `Pung Check Edge` | Service | 주변에 바닥 없는 곳이 있으면 → BB (Bool). 공중에서는 갱신 안 함 |
  | `Pung Aim And Fire` | Task | 반응 시간 동안 대상을 바라보다가 오차를 섞어 발사. 땅에 있는 상대는 확률로 발밑 조준 |
  | `Pung Find Safe Location` | Task | 낭떠러지 반대쪽, 주변에 바닥이 많은 NavMesh 지점 → BB (Vector) |
  | `Pung Has Charge` | Decorator | 충전 N발 이상이면 통과 (중단 모드 미지원) |
  | `Pung Use Item` | Task | 들고 있는 사용형 아이템(펄스 등) 사용. 없으면 실패 |

  - BB 키는 노드 디테일 창에서 고른다. 이동은 기본 `Move To`.
  - 난이도는 `UPungBotProfile` 데이터 에셋 (§10).
- 1차 범위: 적 찾기, 조준 오차를 둔 발밑/몸 사격, 낭떠러지 피하기. ❓ 밀려 떨어질 때 로켓 점프로 복귀는 나중에.
- 봇 디버그 콘솔 명령 (호스트 전용, `APungPlayerController`)

  | 명령 | 동작 |
  |---|---|
  | `PungAddBot [수=1]` | 봇 추가 |
  | `PungRemoveBot [수=1]` | 나중에 들어온 봇부터 제거 |

- 에디터 작업: BB/BT 에셋, `BP_PungAIController` (BT 와 프로필 지정), `BP_PungGameMode` 의 Bot Controller Class 지정, 맵에 `NavMeshBoundsVolume`.

| 점수판 | `APungGameState` | `GetSortedPlayers()` (킬↓, 사망↑, 이름), `OnScoreboardChanged` |
| 킬 피드 | `APungGameState` | `OnPlayerFell(Killer, Victim)` (Killer 가 null 이면 자멸) |

## 13. 웹 원작 레퍼런스 (PUNG!)

- 저장소: https://github.com/Jokkilook/MiniGameChallenge/tree/main/Pung (WebGL, 직접 제작)
- 방침: **수치를 그대로 옮기지 않는다.** 로직과 설계 의도만 가져오고, 수치는 언리얼 버전에서 따로 튜닝한다.

### 가져온 것
- 사격 로직 (§3.1): 즉발 판정, 연출용 탄, 근접 신관, 공중 폭발, 자기/남 반경 분리
- 넉백 후 조작력 감소, 폭발 점프 유예 (§4)
- 아이템 패드와 아이템 4종: 과충전, 닻, 드럼 탄창, 펄스 (§3.6). 수치는 출발점으로 원작 값을 썼다

### 아직 안 가져온 것 (후보)
| 항목 | 원작 동작 |
|---|---|
| 리스폰 무적 범위 | 무적은 남의 넉백만 막고, 자기 로켓 점프는 허용 |
| 아이템 2종 | 리버스 캡슐, 깃털 (나머지 4종은 가져옴, §3.6) |
| 무너지는 아레나 | 15초 후부터 3.6초마다 바깥 링부터 붕괴 |
| 승리 조건 | 먼저 `5 × (인원-1)`점. 킬 인정 3.5초, 즉시 리스폰 |
| 사격 판정 권한 | 쏜 사람 화면 기준으로 맞음 판정 (지연 보정). 언리얼 버전은 조준만 쏜 사람 기준으로 가져왔고, 표적 위치는 아직 서버 기준 |
